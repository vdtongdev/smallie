Short-term, long-term (knowledge graph) and cross-chat memory.

**Memory:**
- Short-term: checkpointer, per conversation.
- Long-term: a knowledge graph per user (`app/core/graph.py`) in plain tables `graph_nodes` (kind `user`/`file`/`entity`; file nodes carry `document_id`, entities an `embedding`) and `graph_edges` (`relation`, provenance `source` = `chat`/`document`/`import`, `document_id`, `conversation_id` without FK), both `user_id`-scoped with ON DELETE CASCADE; laid out as vertex + edge tables so a PostgreSQL 20 `CREATE PROPERTY GRAPH` can sit on top (SQL/PGQ was pulled from PG 19). Only facts touching the User node or a file node are kept. Agents never save facts themselves (free models skipped the optional save call, AP-006): after a finished turn whose answer came from the orchestrator (`_answered_by`; sql/chart/docs lookups are skipped to save calls), the `remember_turn` background task runs `extract_facts`, one call of the orchestrator's model with `with_structured_output(FactUpdate, method="function_calling")` and `EXTRACT_PROMPT` (the user's file names go in the human message); Pydantic is the filter (snake_case relation, ≤ 8 triples), and its tokens go into the usage totals. `save_facts` resolves names: user words → the User node, a file name → its file node, else an entity by exact `normalize`d name, then nearest embedding ≥ `SAME_ENTITY` (measured; re-measure after changing the embedding model), else a new node; a relation in `FUNCTIONAL` replaces the user's old edge; orphan entities are dropped. Against duplicate wording (the same fact saved as `has_name`/`is_named`/`is`): `Fact` maps known wordings to a `STANDARD` relation (`ALIASES`); `EXTRACT_PROMPT` lists `STANDARD` (a test checks it) and the extractor's message lists the user's other relations to reuse; a file -> User link is turned to User -> file; and `_keep_one_edge` keeps one learned edge per node pair (a standard relation beats invented ones, the newest invented one beats older ones, two different standard ones both stay; card edges are left alone). `recall_facts` (SQL only, newest `RECALL_FACTS` edges at the User node) fills `AgentContext.memories`/`MEMORIES_SECTION` through the chat's snapshot; `search_memory` runs `search_facts`; `/api/memories` lists and deletes edges (`list_facts`, `delete_fact`, cards excluded). `scripts.build_graph` starts the graph once per user (`users.graph_built_at`; new accounts get it at signup, so it never touches them): the old store namespace `("users", user_id, "memories")` (converted, then emptied; otherwise only `forget_user` touches it) and every turn of every past chat (`CHAT_BATCH` turns per `extract_from_turns` call, progress in `conversations.mined_turns`, so a rate-limited run resumes), then cards for ready files without one (from their stored chunks). The store's semantic index (pgvector HNSW only supports ≤2000 dims, so larger `EMBED_DIM` switches to a flat index) still serves chat history.
- Memory snapshot (`app/core/snapshot.py`): a chat's profile, facts and other-chat turns (`load_recent_chats`, `CROSS_CHAT_HISTORY`, default on) are frozen in `conversations.memory_snapshot` (jsonb) with `snapshot_at`, and become `AgentContext.user/memories/recent_chats`. `chat_snapshot` reuses the saved snapshot while the chat's last turn (`updated_at`) is within `MEMORY_SNAPSHOT_MINUTES` (default 60), else calls `build_snapshot` and saves it (`save_snapshot`). Deleting a fact (`/api/memories`), a file (`features/documents/routes.py`) or a conversation calls `clear_snapshots(user_id)`, which clears every chat's snapshot of that user and stamps `snapshot_at`. Race rule: `save_snapshot` drops a build that started before or at that stamp, since it may hold deleted data. Facts learned in a chat are in its history, so they are not added to the snapshot. `bench_chat` calls `build_snapshot(None, ...)` once per scenario, so its runs have no other-chat turns.
- Cross-chat history search: after a finished turn a `BackgroundTask` indexes it under `("users", user_id, "history")` (`save_turn`) for the `search_chat_history` tool. Deleting a conversation also deletes its history items (`forget_conversation`).
