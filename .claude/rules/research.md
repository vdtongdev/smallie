Research workflow, citations, MCP servers and skills.

**Research workflow (`app/agents/research/agent.py`):** `StateGraph(ResearchState)` with one node `gather`, compiled as `research`. `gather` invokes the researcher (`research_agent`, cap `RESEARCH_MAX_MODEL_CALLS`) inside the node with `context=runtime.context` (it still streams as a nested subgraph) and stores its final notes in `findings` (or its last raw tool results via `findings_from` when it hit the cap), never in the messages: as a route node the assistant's `findings` key carries them to the orchestrator (which clears it), as the `ask_research` tool `findings_result` returns them. `gather` is a silent step. The date is the researcher's tail note (`TODAY_NOTE`, `tail=` in `build_research_workflow`), not part of `RESEARCHER_SYSTEM`. When Tavily loaded, the researcher prompt gets `WEB_ALONGSIDE_WIKI` (every Wikipedia search comes with a web search in the same step, except for arXiv questions). The orchestrator's citation format (`CITATIONS` in `COMPOSE_SECTION`: `[n]` numbers in paragraphs plus a numbered Sources list at the end, `([source](URL))` at the end of bullets) gets deep links from the researcher: its notes cite `[source: <id> | "quote"]`, where the id (`S` + 4 hex of the URL's sha1, `source_id`) comes from the `[source ids]` list that the `cite_by_id` tool middleware appends to every tool result (`source_index` finds the URLs: Tavily JSON entries and every URL in text results with the text before it as title; `page_text` strips the list again for `pages_from`). Ids keep the notes short, since writing them is the researcher's slowest step (the prompt also caps their length). `expand_source_ids` turns them back into `[source: Title | URL | "quote"]` (unknown ids are dropped, the quote still finds the page), which `link_sources` (in `gather`) rewrites as `[source: <label> | <URL> | passage: <URL>]`, checked against the pages in the researcher's tool results (`pages_from`: Tavily JSON entries and `wikipedia_page` text) plus the whole article of each cited Wikipedia page (`with_wikipedia_articles` → `knowledge.wikipedia_article`, a plain HTTP fetch, not a model call). The first URL is the Wikipedia section the quote is in (or the page), so paragraph facts from one section share one reference number; the passage link adds `:~:text=` and is what list items cite; the label is the page's own title (plus section name). A quote not on any page gets no passage link; a source written without a URL gets the URL of the page containing its quote, or of the one page whose domain matches its label; the write-up rules also name the reply language (`reply_language` in `core/prompts.py`), and `knowledge_wikipedia_page` shows each heading's section URL and, with `section=`, that section plus the articles it links to (so list items can cite their own page). The format is tied to `linkCitations` in `app.js`, which turns `[n]` into superscripts that scroll to item n of the message's last top-level `<ol>`. Don't name an inner node like a route (`research`), or the namespace filter would silence the whole workflow.

**MCP (`app/core/mcp.py`, `open_mcp_tools`):** remote servers (`streamable_http`/`sse`) via `MultiServerMCPClient(tool_name_prefix=True).get_tools(server_name=...)`, so each tool call opens its own session. Local FastMCP servers run in-process via `mcp.shared.memory.create_connected_server_and_client_session`, whose session lives on the lifespan exit stack; **don't use stdio servers**, because asyncio subprocesses fail on Windows' `SelectorEventLoop`, and the Cloud Run image has no Node. Tool names are `<server>_<tool>` (Tavily's become `tavily_tavily_search`/`tavily_tavily_extract`; its credit-hungry `crawl`/`map`/`research` tools are dropped via `SKIPPED_TOOLS` in the research agent). A failing server is logged and skipped. The research servers are configured in `app/features/research/sources.py` (Tavily via `Authorization: Bearer` header when `TAVILY_API_KEY` is set, extra JSON from `MCP_SERVERS`) and live in `app/features/research/mcp_servers/` (`knowledge`: Wikipedia/arXiv over `httpx`, `transport` is swappable for tests; `external_db`: `EXTERNAL_DATABASE_URL` through `readonly_engine()` + `execute_readonly(..., engine)`, the same guard as the SQL agent).

**Skills (`app/agents/skills.py`):** `<dir>/<name>/SKILL.md` with `name`/`description` frontmatter; `skills_section()` goes into the system prompt, `make_load_skill_tool()` returns the body on demand. `skills_inline()` puts every body into the prompt instead; the orchestrator uses it for the answer formats because small models skip the optional `load_skill` call and then ignore the format. Researcher skills are in `app/agents/research/skills/researcher/`, answer formats in `app/orchestration/formats/`. Any agent can reuse this.
