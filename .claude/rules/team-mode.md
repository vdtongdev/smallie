Team mode (task graph): code-level description.

Design: `docs/superpowers/specs/2026-10-26-team-task-graph-design.md` (the round table it replaced: `2026-10-23-agent-team-design.md`, "Phase C v2"). Phase A (shared rooms) is planned, not built. The UI switch turns team mode on for a new chat (`POST /api/chat/team`; an opened chat keeps its `kind`, served by `GET /api/conversations`). With `context.agent == TEAM_MODE` the router answers `team` without rules.

**Graph (`app/orchestration/team.py`, `build_team`; pure plan checks in `team_plan.py`; prompts `PLAN_PROMPT`, `TASK_MESSAGE`, `ROUND_MESSAGE`, `CHALLENGE_MESSAGE`, `CONFLICT_MESSAGE`, `BOARD_PROMPT`, `TEAM_MESSAGE`, `DRAW_MESSAGE` in `orchestration/prompts.py`):** the `team` node of the assistant graph is a subgraph `plan -> dispatch -> speak x N -> review -> dispatch ... -> synthesize -> draw`, with `pause` on a question. Three layers: the plan and follow-ups (orchestrator and judge models), the agents' tasks, and the `workspace` state.

**Plan (`plan`, `ask_plan`, `validate_plan`):**
- `ask_plan` is one structured call (`Plan`: tasks with `id`, `agent`, `goal`, `depends_on`) on the user's model (from Settings; no separate orchestrator model). Its input is the chat so far (`chat_so_far`: earlier human messages and final answers, no hidden notes or tool messages, oldest first, each cut to `PLAN_MESSAGE_LIMIT` characters, the oldest dropped past `PLAN_HISTORY_LIMIT`; added by string concatenation, empty in a new chat), the latest message, and each available agent's `description`, `review`, `sources` and `prompt_note`.
- `validate_plan` drops tasks for unavailable agents, caps at `TEAM_MAX_TASKS`, renumbers ids `t1..`, drops edges to dropped, empty or duplicate ids, and returns `None` for a cycle or when every task was dropped.
- Retry exception (`retry_tasks`, no model call): a message of at most `SMALL_TALK_WORDS` words with `again`, `retry`, `redo`, `rerun`, `thử lại`, `làm lại` or `chạy lại` that would otherwise go `alone`, in a chat whose latest team answer carries `additional_kwargs["team"]`, re-runs that turn's `plan`/`fallback` tasks (pending again, an empty goal replaced by the old goal) and skips the plan call. Other small talk ("thanks") still goes `alone`.
- A failed call or `None` -> fallback plan: `participants()` as independent tasks (`fallback_tasks`, `origin: "fallback"`) and a `plan` event with `fallback: true`. `RateLimitError`/`AuthenticationError` propagate.
- An empty plan, or no speaker in `participants()` (small talk: `is_small_talk`) -> `alone`: the orchestrator answers as in normal mode (a handoff is run on the thread). Exactly one speaker named -> one task, no plan call.
- `participants()` = the agents the latest message names (`is_named`), else every available non-drawing agent, plus every `joins == "with_others"` agent when another one takes part.
- A planned chart task is forced to `depends_on: ["answer"]`, and edges to a chart task are dropped: nothing depends on one.

**Waves (`dispatch`, `speak`):** `dispatch` sends one `Send("speak")` per `ready` task (all dependencies settled in `SETTLED`). A task whose dependencies all ended `failed`/`withdrew`/`skipped` (`dead_inputs`) becomes `skipped` with no call. With no ready task it goes to `synthesize`. A wave ends when all its Sends return. `after_user_files` (team_plan) makes every planned task without `depends_on` wait for the tasks of file-reading agents and records them in `files_first`; `dead_inputs` ignores `files_first`, so those tasks still run when the readers find nothing. The fallback plan has no such waits: every agent runs at once. The task note is `TASK_MESSAGE` (goal, the dependencies' text and table ids, the dead inputs, the instruction to compare the input with its own source and write down any mismatch) or, for fallback and reply tasks (empty goal), `ROUND_MESSAGE`; plus the agent's `RouteInfo.prompt_note`. `speak` keeps its name: it emits `speaker {agent, task, ns}` first, then invokes the agent (remote or local) with the note as a last hidden `HumanMessage(name=TEAM)` and `AgentContext.sources = spec.sources`, so it uses only its own sources. A failed agent becomes status `failed` with a note as text. An agent withdraws (status `withdrew`) when its sources hold nothing: `spec.gave_up`, or no `source_tools` call (answers-directly agents), or no `findings` (research).

**Workspace (`TeamState.workspace`, reducer `merge_workspace`):** `goal`, `tasks` (`id`, `agent`, `goal`, `depends_on`, `status` pending/running/done/failed/withdrew/skipped, `origin` plan/follow_up/fallback/reply), `results` (task id -> newest `{agent, text, tools, artifacts, round}`), `evidence`, `artifacts`, `history` (waves, task results and reviews in order), `rounds_at`, `challenged`, `synthesis` (`forced`, `open_points`, `not_done`), `wave`, `question`. `plan` resets it for every message (a `reset` key); nothing carries over. Only the final answer joins the thread; `_transcript` (the workspace without `rounds_at`, `artifacts`, `challenged` and the results' artifacts) goes on its `additional_kwargs["team"]` with the turn's tables/charts, so a reload shows them. The orchestrator also records the routes it asked in `additional_kwargs["asked"]`.

**Review (`review`, `ask_board` -> `Review`):** one structured call on the user's model (no separate judge model) after a wave: a `Board` (agreements, differences, conflicts, question) plus `challenges`, `outcomes` and `follow_ups`; evidence found goes into `workspace["evidence"]`.
- Skip rules: with tasks still pending, the wave is reviewed only when one of its tasks took input (`depends_on`), or two of its live tasks feed one pending task, or a producer is under challenge. After the last wave the review always runs. No call when no live answer exists, or when the only answer left is one whose siblings withdrew (they already searched their sources and found nothing, so the one live answer stands). A lone task that did not withdraw still goes to the review. A chart task never joins the review or forces the write-up.
- Board rules: the board never decides by the kind of source (database, file, web, model) and uses no outside knowledge. A difference counts as explained only when every side has a source and an as-of date and the explanation fits the size of the gap. `clean` enforces the first part in code: a difference with no sides, or a side without source or date, becomes a conflict (`issue` "a side has no source or date"). `routes` keep only agents that answered, `fixable_by` only the conflict's own routes, `challenges` and `outcomes` only live task ids. `Conflict` and `Difference` carry `cause` (`definition`, `date`, `source`, `error`, `unknown`). `question` is set only for information only the user has.
- A failed review call becomes an empty review with `forced`; dispatch continues.
- Hand-off challenges: a `Challenge` (`to_task`, `by_task`, `question`, `evidence`) sends the producer one round with `CHALLENGE_MESSAGE`. The next review reports an `Outcome` per challenged task. Revised: the done tasks that depend on it run again (status back to `pending`). Stands: `"<task> stands: <question>"` joins `synthesis.open_points`.
- Meeting conflicts: a conflict with a non-empty `fixable_by` and no question starts a conflict round (`CONFLICT_MESSAGE`) for those tasks only.
- Rounds: `rounds_at` counts extra rounds per meeting point, keyed `hand_off_key(to, by)` (`"t1->t2"`) or `meeting_key(task ids)` (`"meet:t1,t2"`). Each key gets at most `TEAM_MAX_ROUNDS`. Past the cap, or after a failure, `forced` is set and the open point goes to the write-up. Normal waves and follow-ups do not count.
- Follow-ups (`add_follow_ups`): taken only from a review that compared, had no question and did not fail. They pass the plan's checks (available agent, `depends_on` only on existing task ids and never on a chart task), a follow-up with an unknown or unavailable agent or a missing dependency is dropped silently (not counted in `synthesis.not_done`), a repeated agent and goal is dropped, and they count toward `TEAM_MAX_TASKS` (the rest go to `synthesis.not_done`). A chart follow-up waits for `answer`, and is dropped (not counted in `synthesis.not_done`) when the turn already has a chart task. Added tasks get `origin: "follow_up"` and a `plan_updated` event.

**Chart task (`draw`):** a chart task has `depends_on: ["answer"]` (`ANSWER`), so `dispatch` never sends it. After `synthesize`, `draw` runs each pending one once on the thread plus the final answer (`DRAW_MESSAGE`) with `sources = NO_SOURCES` (no data tool); its charts join the answer (same message id). `chart_data` is denied (`deny_tools`) when the answer carries tables, so it charts the table with `chart_table`; with no table it charts the figures written in the answer with `chart_data`. The write-up orchestrator gets `chart_table`/`chart_data` denied (`team_drawn`) when the workspace has a chart task. A failed chart task leaves the answer without a chart.

**Write-up (`synthesize`):** one live answer from an answers-directly agent, no conflicts, not `forced`, no open points or `not_done` -> that agent's answer stands (no `synthesize` event, no extra call). Every agent withdrew -> `NOTHING_FOUND_MESSAGE`. Otherwise the orchestrator writes from `TEAM_MESSAGE` (answers, differences with `cause`, conflicts, open points, tasks not done), passed as `team_note` (hidden message named `TEAM_MODE`, in `HIDDEN`, so `is_composing` is true and it writes without tools). Its rules: name the cause, keep what was observed (sql, docs) apart from a possible explanation (research, reasoning), name open points, tasks that never ran and follow-ups dropped by the cap. If it hands off instead, the joined answers stand.

**Budget stop:** `CallBudgetExceeded` (`RemoteAgent`) in `speak` marks the result `budget`; `dispatch` then goes to `synthesize`, and the write-up names the tasks still pending.

**Pause and resume:** a non-empty `question` makes `review` emit `needs_human` and go to `pause`, which calls `interrupt` and nothing else (the node reruns from its start on resume); the question joins the thread as an orchestrator `AIMessage`. `_chat_input` (routes_chat) turns the next `team` message into `Command(resume=message)` while `aget_state(config).interrupts` is set. A reply that names an agent not taking part yet adds a task with `origin: "reply"` and no dependencies, runs one wave (`dispatch`), then `review`; any other reply goes straight back to `review`. `remember_turn` returns early when the snapshot has interrupts. `GET .../messages` appends the pending question with `pending: true`.

**Independent sources:** `scope_tools` (`wrap_model_call`, `agents/factory.py`) offers a team request only the tools whose `TOOL_SOURCE` tag (`tool.metadata`) is in `context.sources`; untagged tools (memory, skills) stay. A model may still call a hidden tool, because prompts name it, so `refuse_hidden_tools` (`wrap_tool_call`) answers it with an error ToolMessage; both use `_in_scope`. Tags: `run_sql` and `chart_sql` `market_db`, `search_documents` `user_files`, research's MCP tools via `tag_mcp` (`tavily_*`/`knowledge_*` `web`, `external_db_*` `external_db`). `research_prompt_extra` builds the researcher's source list, skills and market schema per request from `context.sources`, so a team researcher is not told about sources it cannot use.

**Transcript and tools:** `ToolRecorder` (`agents/base.py`, async callback) records each tool call as `{name, args, result}` (result cut to `TOOL_RESULT_PREVIEW`), inner calls of a workflow included, memory tools excluded. In-process, `speak` passes it in the config; an agent server runs its own and returns the list as `tools` in its result (`server.py`), which `RemoteAgent` passes on. Without either, `_tools(turn)` scans the messages.

**Custom events (stream mode `custom`, `get_stream_writer`):** `speaker` is internal: `{agent, task, ns}` tells `_events_from` which `speak:<task id>` namespace runs which agent, and is dropped. `TEAM_EVENTS` (routes_chat) reach the UI: `plan` (`tasks`, `fallback`), `plan_updated` (the added `tasks`), `wave` (`wave`, `kind` plan/challenge/conflict, `tasks`, `agents`), `spoke` (`task`, `agent`, `text`, `tools`, `withdrew`), `review` (the `Review` plus `key`, `forced`), `synthesize` (only on a write-up), `needs_human` (`question`), `charts`. `_events_from` finds the namespace segment that is in `speakers`: `token`/`tool_call`/`tool_result` events inside it get that `agent`, and `_to_events(in_round=True)` lets silent steps stream (research's notes are its answer).

**UI (`app/static/app.js`):** every reply, team or not, has a status line (spinner, `Wave n/total` with agent badges, a challenge or follow-up note from `reviewNote`, "using <tool>", "writing"; afterwards the wave count, resolved challenges and explained differences) and an **Activity** button opening a popup (`renderActivity`) with the plan, each wave's answers and tool calls, each review and a pending question; a chart task's answer sits under `drawn`. There are no inline tool lines in the chat. A reload builds the popup from `message.team` (`teamActivity`) or the tool messages; `teamActivity` still reads the round table's `rounds`/`boards` shape, so old team chats show their rounds.

**Language:** `REPLY_LANGUAGE` is appended on every orchestrator call (from `reply_language()` of the user's messages, hidden ones left out); the team prompts take `{language}`. `MEMORIES_SECTION` ends with a line that a stored language preference never changes the reply language (AP-007).

**Settings:** `TEAM_MAX_TASKS` (6, plan and follow-ups together), `TEAM_MAX_ROUNDS` (2, per meeting point), `TEAM_MAX_MESSAGE_MODEL_CALLS` (30, `RemoteAgent`'s guard for team requests), no judge or orchestrator model setting: the plan, the review and the write-up all use the account's model from Settings (the per-role model settings were removed). Measured with the old fixed models (not the task graph's; the round table's board): with Gemma as judge a planted wrong figure was not flagged (29 calls, 189 s); `deepseek/deepseek-v4.1-flash` flagged it in 1 round / 9 calls / 99 s and settled the plain scenarios in 1 round / 6 calls (49 s; chart 74 s), under $0.01 per message; Haiku 5.5 was faster per call but looped 4 rounds on a small date gap. Task graph, measured 2026-10-26 (15 scenarios, 100 calls, no fallback): 2 calls for no specialist, 4 for the stock question (26 s), 7 for the planted error (flagged), 15 for all agents; choice precision and recall 1.00. Not yet seen live: a follow-up (`team_e_followup`: the planner planned sql up front) and a file-vs-database conflict (`team_conflict`: docs withdrew). `contribution.used` reads "unused" for agreeing answers (evidence comes only from differences and challenges).
